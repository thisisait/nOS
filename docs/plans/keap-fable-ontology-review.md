## Goal
One slow, careful **fable** (`claude-fable-5`) pass with COMPLETE context and NO
sub-agents — maximal "AIQ" on a whole-map judgment that fan-out would fragment:

1. **Anchor verdict** — given the full L0-2 spine, does anything on the first three
   levels need adjusting (rename / re-describe / re-parent / insert / split / merge)?
   Expected default: **bless it** — L0-2 is the curated spine, and any edit re-bakes
   the U1 star layout (every existing star moves, `layoutVersion` bumps). Propose an
   anchor edit ONLY for a genuinely structural flaw (a missing top-level science, a
   miscategorised L1), never for style.
2. **If the spine is sound → propose new blocks** for the most *important but sparse*
   domains, returning a structured output of up to several hundred records.

## Why fable + no sub-agents + full context
The curator's fan-out was for *parallel* per-pillar consolidation. "Is the ontology
spine correct?" and "where are the important gaps?" are **holistic** judgments that
want one strong mind seeing everything at once — sub-agents would lose cross-domain
coherence. fable has the highest AIQ; give it the whole picture and let it reason.

## Phase 4 — ingestion (reuse the proven pipeline)
- **new_blocks → `import-domain.mjs` bundle per domain**, NOT hundreds of individual
  promotions (that would flood moderation). Convert fable's `new_blocks` into a
  `deploy/<domain>-import.json` (root pillar + blocks + brief), then
  `docker exec iiab-keap-1 node deploy/import-domain.mjs <domain>` →
  `docker restart iiab-keap-1` → embed-sync. Idempotent, U1-preserving append (same
  path as math/chem/bio — see memory `keap-domain-deep-import-epic`). Operator
  reviews the BUNDLE, not 300 rows.
- **anchor_verdict.proposed_edits → a high-scrutiny review doc** for the operator.
  Any L0-2 edit re-bakes the layout, so it is a deliberate, supervised change — never
  auto-applied. Most likely this list is empty.

## Depth vs breadth — recommendation
The per-pillar workflow (math/chem/bio) gave DEPTH (1 agent/pillar, schema-validated,
~15 blocks with real definitions each). A single fable call producing hundreds of
blocks trades some per-block depth for **coherence + prioritisation**. Best split:
let fable do what only it can — **the anchor judgment + the skeleton + the priority
ordering + one strong block draft each**. If a domain needs full ToE-level depth,
run a focused follow-up per-domain workflow (the proven pipeline) on fable's
skeleton. If fable's budget allows deep drafts in one pass, even better — highest AIQ,
let it. Consider chunking by top-N sparse domains so each gets full attention rather
than 300 shallow records.
