# SnappyMail

> Modern, fast PHP webmail client (successor to RainLoop). An IMAP/SMTP frontend
> — users log into their own mail accounts inside the app. Stateless: no
> database; all config lives in the data directory. Defaults its login page to
> the Stalwart mail server when installed.

## Authentication

- **Admin user:** none provisioned by nOS. The SnappyMail admin panel is at
  `/?admin` (its own admin password is generated by the image on first boot and
  stored in the data directory).
- **End-user login:** users authenticate with their **IMAP account** inside the
  app — that account is the identity; no per-user identity flows in from Authentik.
- **SSO bucket:** `forward_auth` (Tier 3 = user). No native OIDC — Authentik
  gates access to the webmail UI at the Traefik layer only.
- **Default mail hosts (shown on the login page, set via the admin panel):**
  `snappymail_default_imap_host` / `snappymail_default_smtp_host` — default to
  `stalwart_domain` when Stalwart is installed, else `mail.<tenant_domain>`.

## API Access

- **None for agents.** SnappyMail is a webmail UI. There is no bot/REST API
  surface provisioned. Configuration is done through the `/?admin` admin panel;
  the `SNAPPYMAIL_DEFAULT_*` environment variables in the compose fragment are
  informational/reserved (the image has no env-var config for IMAP/SMTP defaults).

## Health Check

- **Endpoint:** `GET /` on container port `8888`.
- **Expected:** `200 OK` (the compose healthcheck runs `curl -f http://localhost:8888/`).

## Dependencies

- An IMAP/SMTP server to connect to — Stalwart (`install_smtp_stalwart`) in a
  production mail stack, or Mailpit for dev capture.
- Authentik (SSO forward-auth gate, optional).
- Traefik (edge proxy + TLS termination + `authentik@file` middleware).
- No database — stateless; all state is in the data directory.
