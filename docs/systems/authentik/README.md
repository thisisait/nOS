# Authentik

> The SSO/IdP organ. Central identity and access management for every nOS service —
> OIDC providers, proxy (forward-auth) providers, RBAC groups and the expression
> policies that bind them. Runs as two containers (server + worker) in the `infra`
> stack; its authoritative state lives in PostgreSQL, not on disk.

## Quick Reference

| | |
|---|---|
| **URL** | `https://auth{host_alias_seg}.{tenant_domain}` (default `https://auth.dev.local`) |
| **Port** | `9003` (`authentik_port`; loopback publish `127.0.0.1:9003` → container `9000`) |
| **Stack** | `infra` |
| **Node id** | `nos.infra.authentik` |
| **Toggle** | `install_authentik: true` |
| **Image** | `ghcr.io/goauthentik/server:2026.5.2` (`authentik_version`) |
| **Containers** | `infra-authentik-server-1`, `infra-authentik-worker-1` |
| **Compose** | `~/stacks/infra/docker-compose.yml` (+ override `~/stacks/infra/overrides/authentik.yml`) |
| **Data** | `{{ nos_data_root }}/platform/services/authentik/data` (default `~/nos/platform/services/authentik/data`) — mounted as **subpaths**, not as one volume: `…/media` → `/media`, `…/templates` → `/templates`, `…/certs` → `/certs` (worker only) |
| **Authoritative state** | PostgreSQL database `authentik` (user `authentik`) on `postgresql:5432` + Redis. The bind mount holds only uploaded media, email templates and issued certs — **it is not the identity store** |
| **Config (not data)** | `~/stacks/infra/authentik/blueprints` → `/blueprints/custom:ro` — rendered YAML blueprints, correctly under `stacks_dir` |
| **Memory limit** | server `2g` (`authentik_mem_limit` → `docker_mem_limit_critical`), worker `1g` (`authentik_worker_mem_limit`) |
| **Networks** | `infra_net` + the shared stacks network (`shared_net`) |

`authentik_version`, `authentik_domain` and `authentik_port` are pinned in
`default.config.yml` — that file **outranks** the role defaults, so bump the version
there. `authentik_data_dir` is defined only in `default.config.yml`; an
external-storage override relocates it to `{{ external_storage_root }}/authentik`
(`tasks/stacks/external-paths.yml`).

## Authentication

- **Admin user:** `akadmin`
- **Admin password:** `authentik_bootstrap_password` = `{global_password_prefix}_pw_authentik_admin`
  (`default.credentials.yml`), re-applied by the `00-admin-groups` blueprint on **every**
  container start — the password is declarative, not one-shot.
- **Admin UI:** `https://{authentik_domain}/if/admin/`
- **SSO:** N/A — this *is* the SSO provider (`traefik_auth_modes: authentik = none`).

## API Access

- **Base URL:** `https://{authentik_domain}/api/v3/`
- **Auth method:** Bearer token (Authentik API Token)
- **Token:** `authentik_bootstrap_token` — a 32-byte hex value **generated by the playbook**
  (`main.yml`), pinned as the `key:` of the bootstrap API token in
  `roles/pazny.authentik/templates/blueprints/00-admin-groups.yaml.j2`, persisted to
  `~/.nos/secrets.yml`, and exported to Wing as `AUTHENTIK_BOOTSTRAP_TOKEN`
  (`roles/pazny.wing/templates/wing.env.j2`). This is what `tasks/tofu-authentik.yml`,
  `tasks/gdpr-export.yml` and `tasks/gdpr-forget.yml` authenticate with.
- **Agent identities:** machine-to-machine agents get OAuth2 clients from
  `authentik_agent_clients` (`default.config.yml`) — `nos-openclaw`, `nos-wing`,
  `nos-state-manager`, `nos-inspektor`, … each scoped by a `capabilities` list.
- **No `openclaw-bot` service account exists.** The `openclaw-bot` /
  `~/agents/tokens/<system>.token` convention documented in `files/openclaw/AGENTS.md`
  is a **design convention, not a provisioned artifact** — no role creates that account
  or writes that file (`~/agents/` itself is created by `pazny.openclaw`; `tokens/` is not).
  Use `authentik_bootstrap_token` or an `authentik_agent_clients` entry instead.

## Health Check

- **Endpoint (manifest):** `GET /-/health/live/` → **`204 No Content`**
  (`state/manifest.yml` `expect_status: 204`, timeout 15s).
- **Readiness probe (role):** `roles/pazny.authentik/tasks/health.yml` polls
  `http://127.0.0.1:9003/-/health/ready/` accepting `200` **or** `204`,
  30 retries × 5s.
- The worker's compose healthcheck carries `start_period: 120s` so cold-start DB
  migrations don't fail the whole `infra` stack.

## OIDC Providers

Providers and applications are **not** read from the central `authentik_oidc_apps`
list any more — D1.3 (2026-05-05) retired it and it survives only as an empty stub
plus the Tier-2 `apps_runner` extension channel. The source of truth is the per-plugin
`authentik:` block in `files/anatomy/plugins/<svc>-base/plugin.yml`, harvested by the
`authentik-base` aggregator into `inputs.clients` and rendered into the
`10-oidc-apps.yaml` blueprint.

Engine selection is `authentik_engine` (`default.config.yml`), default **`blueprint`**.
Setting it to `tofu` hands providers, applications and outpost attachments to OpenTofu
(`docs/opentofu-authentik-cutover.md`); the other blueprints still apply imperatively.

To reconverge after changing a plugin's `authentik:` block, include
`pazny.authentik` with `tasks_from: blueprints.yml` then `meta: flush_handlers` —
`health.yml` does *no* post-deploy work despite the legacy name it replaced.

## Dependencies

- PostgreSQL (identity store — required; `AUTHENTIK_POSTGRESQL__SSLMODE: prefer`,
  `CONN_MAX_AGE: 0` so Authentik does not exhaust the shared connection pool)
- Redis (cache / dramatiq broker — required)
- Mailpit (SMTP relay, only when `install_mailpit` — optional)
