# The design system — where the look of nOS is decided

The visual language of This is AIT and nOS lives in its own repository,
**https://github.com/thisisait/design** (`@thisisait/design`): one `tokens/tokens.json`
(colour per theme, type, spacing, radius, size, shadow), a component layer, HUD screens,
Iris' eye and a machine-readable catalog for generative UI. Themes are `civic` (the
default everywhere), `civic-dark`, `ledger`, `ledger-dark`, `glass`, `glass-dark` and
`glass-face` — the running face desktop.

This repo never fetches it. What it needs is vendored, pinned to a commit, and gated:

| copy | consumer | gate |
|---|---|---|
| `files/anatomy/design/tokens.json` | `tools/cc/theme.py` (nos-cc, generated by `tools/design-sync.py`) | `tests/anatomy/test_cc_theme_is_design_tokens.py` |
| `files/anatomy/design/tokens.json` + `components.css` (the glass filter; tokens.json has no effect group) | the face organ: `files/anatomy/face/src/lib/design/tokens.css` (generated; the face keeps `--bg/--glass/--ok…` as aliases, app.css derives only the state tints the design lacks) | `tests/anatomy/test_face_tokens_are_design_tokens.py` |

Not yet on the design system: Wing (`files/anatomy/wing/www/assets/tokens.css`, pinned by
`tests/anatomy/test_wing_ui_tokens.py`; migrate by generating that file from tokens.json
while keeping its legacy aliases) and apex (`files/anatomy/apex/assets/ait.css`, the brand
source the system was derived from).

Rules an agent should keep (reasons in the design repo's CLAUDE.md): red is state only;
`ok` is blue-side so state never depends on red/green vision; UNKNOWN is dashed and never
green; no remote fonts or CSS, the estate runs offline; a generative UI composes only from
`catalog/components.json`.

To update: `python3 tools/design-sync.py ../design` (copies tokens.json, regenerates the
nos-cc theme and the face tokens, bumps the pin), then the face's own `tools/sync-design.sh` in nos-face.
