# Secret lifecycle + recovery doctrine (SEC-13, 2026-05-23)

> Authoritative doc for the systematic security pass triggered 2026-05-23
> after the Infisical-login lockout incident. Cross-references the SEC-1
> through SEC-12 commits that implement each pattern.

## The problem this doc fixes

nOS treated secrets as **Ansible variables** (re-derived from
`global_password_prefix` on every run). The deployed artifact (the
admin row in Infisical PG, the API key in Authentik DB, the env block
in a launchd plist, the value in a Docker container env) was captured
**once at bootstrap** and never reconciled against the Ansible-derived
value afterwards.

The drift class this creates:

| Surface | Captured at bootstrap | Re-derived every run | Drift consequence |
|---|---|---|---|
| Infisical admin email | `admin@gmail.com` (a stale operator config) | `admin@pazny.eu` (current) | Operator can't log in. Only recovery: `blank=true`. |
| Authentik akadmin password | derived from prefix `pX_pw_*` | derived from current prefix `pY_pw_*` (after rotation) | Same. |
| HMAC secret default | `changeme_pw_bone` (15 chars) | same — but `changeme` is in attacker dict | Brute-forceable. |
| Plugin compose-extension OIDC client_secret | rendered into `~/stacks/*/overrides/*.yml` (mode 0644!) | re-rendered into same file | Plaintext leak to any local UID. |

## The four canonical patterns

The systematic fix is to push every secret class into ONE of four
explicit categories:

### Pattern A — Derived (Ansible-canonical)

Cheap-to-recompute values that aren't security-sensitive on their own:
service URLs, container image tags, file paths.

```yaml
infisical_domain: "vault.{{ tenant_domain }}"   # derived, no drift risk
```

Rule: re-derive on every run. No persistence. Operator changes via
`config.yml` override. **No drift detection needed.**

### Pattern B — Auto-generated (one-shot capture)

High-entropy random values that protect secrets at rest or in transit:
HMAC keys, JWT signing secrets, app encryption keys.

```yaml
# main.yml::Lazy-regenerate placeholder APP_KEYs / tokens
bone_secret: "{% if '_pw_' in (bone_secret | default('')) or (bone_secret | default('') | length) < 32 %}{{ lookup('pipe', 'openssl rand -hex 32') }}{% else %}{{ bone_secret }}{% endif %}"
```

Rule: generate via `openssl rand -hex 32` (or `-base64 32` for tokens
that may transit URLs). Persist to `~/.nos/secrets.yml` (mode 0600).
Subsequent runs reuse the persisted value. Operator override in
`credentials.yml` wins if ≥32 chars and doesn't match the prefix-
derived shape.

**Shipped:** SEC-3 (`bone_secret`, `wing_events_hmac_secret`,
`nos_deploy_hmac_secret`). Other entries already followed this pattern:
`outline_secret_key`, `firefly_app_key`, `bookstack_app_key`,
`infisical_encryption_key`, `infisical_auth_secret`,
`authentik_secret_key`, `bluesky_pds_rotation_key`, etc.

### Pattern C — Captured-not-derived (DB-canonical)

Identity values that live INSIDE a service's database after bootstrap
and shouldn't change underneath the playbook: admin emails, admin user
UUIDs, service IDs assigned by an external system.

Rule: at first bootstrap, capture the deployed value into
`~/.nos/state.yml::deployed.<service>.<field>`. Subsequent runs READ
from state.yml; Ansible variables become operator-recommendations,
not canonical truth. If captured ≠ derived, surface a calibrated
warning + offer migrate path.

**Shipped (partial):** `infisical_users_project_id` is the first
example (SEC-A18 follow-up). UUID generated by Infisical on first
seed, captured to `~/.nos/secrets.yml`, all subsequent operations
reference the captured value.

**Queued:** capture pattern for `infisical_admin_email`,
`authentik_bootstrap_admin_uuid`, `gitea_admin_user_id`,
`portainer_admin_id`. Without these, every admin-bootstrapping role
will eventually hit the same lockout class as Infisical did 2026-05-23.

### Pattern D — Recoverable (break-glass reset path)

For when Pattern C captured a value the operator subsequently lost OR
when bootstrap was done with stale config that no longer matches
operator intent. EVERY admin-bootstrapping role must ship a `reset.yml`
task.

```yaml
# Invocation (tag-gated, never-by-default):
ansible-playbook main.yml --tags <service>-reset-admin
```

The reset.yml task MUST:
1. Pre-check that the operator's deployed data is empty (zero
   projects + zero secrets, etc) — refuse otherwise unless
   `<service>_reset_force=true`.
2. Forensic-discover the currently-deployed admin (email, ID) and
   report it to the operator in a `debug:` block. Operator can still
   choose to log in with the deployed creds if they're known.
3. Truncate the service's user/org tables in DB (FK-safe CASCADE).
4. Clear any persisted tokens/identities in `~/.nos/secrets.yml`.
5. Re-invoke the bootstrap chain. New admin = current Ansible-derived
   values (Pattern A).

**Shipped:** SEC-5 = `roles/pazny.infisical/tasks/reset-admin.yml`.

### Per-service recovery posture

Not every service needs a `reset.yml` — some have Pattern D built into
their bootstrap mechanism. Catalog:

| Service | Recovery mechanism | Why explicit reset is / isn't needed |
|---|---|---|
| **Infisical** | `--tags infisical-reset-admin` (SEC-5) | One-shot `infisical bootstrap` CLI; no reconverge. Lockout class confirmed live 2026-05-23. |
| **Authentik** | Blueprint reconverge on every playbook run (`files/anatomy/plugins/authentik-base/blueprints/00-admin-groups.yaml.j2`) re-applies akadmin email + password from current Ansible-derived values | Built-in Pattern D. Operator's `ansible-playbook main.yml --tags authentik` IS the recovery. No separate reset.yml needed. |
| **Gitea** | `--tags gitea` re-runs `gitea admin user change-password`-style task (see `roles/pazny.gitea/tasks/post.yml`) | Built-in Pattern D-ish via the admin-user reconverge step. |
| **Portainer** | `roles/pazny.portainer/tasks/post.yml` resets admin via Portainer API on each run | Built-in. |
| **Vaultwarden** | NO admin reset path today. Operator-tier vault, secrets are user-encrypted. | **Pattern D queued** if operator-lockout class surfaces; for now, blank=true is the only recovery (acceptable since Vaultwarden is per-user, no admin DB content to preserve). |
| **ERPNext** | `bench set-admin-password` invoked in `roles/pazny.erpnext/tasks/post.yml` | Built-in Pattern D. |
| **WordPress / BookStack / Outline / FreeScout / Miniflux / HedgeDoc / Firefly** | Each role's `post.yml` re-runs the service's admin-creation step on every playbook run | Built-in Pattern D via reconverge. |

**Operator playbook for any admin lockout:**
```bash
# Step 1: try the per-service tag (almost always sufficient)
ansible-playbook main.yml --tags <service>
# Step 2 (Infisical only): explicit force-reset with data-wipe gate
ansible-playbook main.yml --tags infisical-reset-admin
```

Operators should NEVER need `blank=true` for an admin lockout. If they
ever do, that's a missing reset path — open a SEC-N ticket.

## File-mode policy (every secret lives in 0600)

| Path | Mode | Owner | Why |
|---|---|---|---|
| `~/.nos/` | 0700 | operator | UID enumeration surface |
| `~/.nos/secrets.yml` | 0600 | operator | persisted Pattern B + C values |
| `~/Library/LaunchAgents/eu.thisisait.nos.*.plist` | 0600 | operator | embeds env-block tokens (Wing/Bone/Pulse) |
| `~/stacks/*/overrides/*-base.yml` | 0600 | operator | plugin-loader rendered OIDC + DB env |
| `~/stacks/*/overrides/` (directory) | 0700 | operator | UID enumeration of service set |
| `<acme>/<zone>.key` | 0600 | operator | wildcard LE private key |
| `<acme>/<zone>.cer`, fullchain | 0644 | operator | public trust anchor — OK |
| `~/wing/app/log/` | 0700 | operator | Tracy exception dumps may have residual env |
| `credentials.yml` (operator) | 0600 | operator | operator overrides |

**Enforced by:** `tests/anatomy/test_security_file_modes.py` sweeps
every `ansible.builtin.{copy,template,file}` task, asserts secret-
shaped destinations carry mode 0600 (or 0400).

## Network exposure policy

| Service | Bind | Reachable | Auth |
|---|---|---|---|
| Wing | 127.0.0.1:9000 (per plist) | host loopback only | forward-auth headers from Traefik (SEC-6 will add edge-token signing) |
| Bone | 127.0.0.1:8099 | host loopback only | HMAC |
| Pulse | n/a | n/a | — |
| Anatomy daemons via Traefik | public TLD | yes | `authentik@file` middleware + scoped routes (e.g. Stalwart `/admin` only) |

**Pattern:** anatomy daemons NEVER bind 0.0.0.0. Public access goes
through Traefik with explicit middleware + path scope.

## How to add a new admin-bootstrapping service

Checklist for the next person adding a `pazny.<service>` role with an
admin user:

1. **Bootstrap path** in `tasks/post.yml`. Captures admin token to
   `~/.nos/secrets.yml::<service>_admin_token`. Idempotent on subsequent
   runs (skips bootstrap when token present).
2. **Capture-not-derive** — at first bootstrap, ALSO persist
   `<service>_admin_email` and `<service>_admin_user_id` (Pattern C).
3. **Reset path** in `tasks/reset-admin.yml`. Mirror the Infisical
   template. Tag-gated `[<service>-reset-admin, never]`.
4. **Hard rule on the plist file mode**: 0600 (SEC-1 anatomy gate).
5. **HMAC secrets** if any: declare via lazy-regen in main.yml's
   block (Pattern B), persist to `~/.nos/secrets.yml`.
6. **No secrets in compose env directly** — render via plugin
   compose-extension (which now writes 0600 per SEC-1).
7. **Anatomy gate** in `tests/anatomy/test_<service>_*.py` pinning
   the contract: token captured, reset task present + tag-gated,
   plist 0600.

## Retired-but-published keys (added 2026-08-13)

`.gitleaks.toml` has said since 2026-06-10 that a real finding "must NEVER be
allowlisted — rotate + purge instead" and cited this document. Until today this
document had no such section: the citation pointed at doctrine that did not
exist. Written now, from the first case that needed it.

**The case.** 2026-08-05, commit `710be435`: the live `bone_secret` was pasted
into a test fixture and pushed to the PUBLIC repo. Sanitising on 2026-08-06
missed a second copy (an assertion needle), which stayed published until
2026-08-13. The key was rotated at discovery — the leaked value is
`bone_secret_retired` in `~/.nos/secrets.yml`, the live key differs — but the
value remains readable in git history on GitHub today.

**The rule.** A secret that has ever been pushed to a public remote is BURNED,
permanently, regardless of later deletions:

1. **Rotate immediately** — this is the security fix, and the only step that
   removes live exposure. Everything after it is hygiene and record-keeping.
   (For `bone_secret` the estate's key-ring verification —
   `AuditChain::chainKeys()` — keeps history verifiable across the rotation.)
2. **Never treat the published value as secret again** — not as a fixture,
   not as a needle in an assertion, not as an allowlist entry. The
   `test_a_fixture_is_never_a_real_secret.py` gates exist because both misuse
   shapes actually happened.
3. **History purge is a separate, operator-only decision.** Rewriting a public
   repo's history (`git filter-repo` + force-push) breaks every clone, every
   PR base, and the release tags — and does NOT un-publish the value (forks,
   scrapers and GitGuardian already have it). Its only benefit is stopping
   FUTURE scanner noise on the old blob. The default disposition is therefore
   **rotate + record, do not rewrite**; a purge is warranted only when the
   operator judges the ongoing-noise cost higher than the history-break cost,
   and it is never an agent's call.

record instead of re-investigated):
